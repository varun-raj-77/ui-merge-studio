Those selected components already existed in the foundation, so that control does not exercise new-component integration expansion.

Prompt 015 retained that failing checkout and ran the same pinned commits in a separate disposable checkout. `replace-jsx-region` records and executes an AST-selected direct-child insertion: one source occurrence, one structurally matching base parent, a unique unchanged sibling anchor (or an empty parent), unchanged declaration structure outside the parent, selected-region source hash, target declaration precondition, and projected declaration postcondition. `PageContent` inserted only `<WorkspaceStatusBanner />` before the unchanged `Card`; `RevenueTrendChart` inserted only `<RevenuePulseBadge />` before the unchanged map expression. Prompt 015F closed two remaining over-inclusion paths. JSX nested inside an expression is no longer copied through `replace-child`, and a failed region projection can no longer invoke the former `single-render-delta-declaration` fallback. Both adversarial shapes now refuse before a candidate worktree or ref exists. At that milestone the legacy controlled `CategorySidebar → CatalogueWorkspace` and Quick View `→ ProductGrid` declaration-wide rewrites also refused, so its Phase-0 verdict remained **MODIFY** despite the external direct-child scenario being green.

Prompt 015G aligns the controlled fixture with that already-proven boundary without changing production transformation logic. Branch A now inserts a context-driven `CategorySidebar` as a direct child of the unchanged `CatalogueWorkspace` parent. Branch B inserts `ProductQuickViewShelf` as a direct child of the unchanged `ProductGrid` parent; the shelf owns configured launchers, selection state, and the existing accessible dialog. The unrelated Vite regression last passed unchanged under Prompt 015F, but its required Prompt 015G rerun was prevented before execution by the environment's exhausted approval quota. ## Phase 5 foundation evaluation

Plan version 2 makes Main, Version A, or Version B an explicit pinned foundation. Fresh-production browser journeys prove separate foundation/addition grouping, configured A and B semantics, redundant-selection explanation, safe refusal, complete-plan history, keyboard radios, reduced motion, and mobile reachability. The configured browser remains an honest adapter projection, not a Git checkout.

Local integration tests create real temporary worktrees from each selected foundation commit. The Version A proof preserves every file changed from the shared base and adds only Desk Stand and Task Lamp Quick View slices; the Version B proof preserves its complete inventory and five-Quick-View diff and adds the Version A sidebar. Each proof installs, typechecks, tests, builds, runs the fixture browser checks, repeats generation, and compares candidate trees. The intentionally incompatible Product-ID foundation is refused before a candidate branch is presented.

The final fresh-production run measured 385 ms from foundation change to dock acknowledgement, 479 ms from View Combined to configured result, and 119 ms to undo the foundation change. The final isolated generation run measured 55.182 s from Main, 55.324 s from Version A, and 60.282 s from Version B before the deterministic repeats. These fixture measurements do not establish a general speed improvement; a larger foundation can add checkout, installation, and verification cost in proportion to its repository diff and dependency surface.

## Local canonical-plan causality proof

The real local App now builds Integration Plan V2 from server-issued foundation and analyzed-selection metadata. Before analysis, the preview Vite transform privately registers random opaque receipt-to-source mappings for the exact session and commit. Normal rendered-selection messages and public analysis requests contain only that receipt; the server resolves source path, declaration identity, and location from its private mapping. Its preflight and generation requests contain only `plan` and `planIdentity`. The server canonicalizes the plan, recomputes the identity, validates the pinned Main/source commits and common ancestor, and resolves every selection through current preview-session-owned analysis before projecting validated artifacts into the existing deterministic generator.

The enabled hermetic Playwright journey launches Branch A and Branch B in detached worktrees, clicks the rendered Category Sidebar and Desk Stand Quick View regions, confirms both decisions, observes receipt-only analysis requests and the exact same canonical plan at preflight and generation, waits for real verification, and launches the generated candidate branch in another runtime-managed worktree. The final preview session commit is asserted equal to the generated candidate commit. The candidate sidebar filters the live product grid, the Quick View opens its real dialog, and the promotional banner and inventory summary remain absent. A separate server-level browser test submits browser-authored source metadata for the unclicked Branch A `PromotionalBanner`, guesses an opaque receipt, and attempts a forged plan; those requests are refused without Git, worktree, or process mutation.

This evaluation establishes normal-flow and current-session provenance, not tamper-proof evidence of a physical click. Phase 0 trusts the local developer and local browser/processes: transformed Vite modules are browser-readable, so a developer can deliberately recover a valid registered receipt and manually call the localhost analysis API without clicking that boundary. Protection against that intentional local bypass is outside the Phase-0 threat model.

The exact serialized-plan replay test recognizes the second generation as idempotent and returns the same candidate tree.
