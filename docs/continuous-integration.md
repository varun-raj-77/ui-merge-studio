# Continuous integration

The [UI Merge Studio verification workflow](../.github/workflows/verify.yml) runs automatically on pull requests targeting `main` and pushes to `main`. It is intentionally read-only (`contents: read`), without repository write credentials, production smoke calls, or manual deployments.

## What it verifies

The workflow uses an Ubuntu 24.04 runner with the official `mcr.microsoft.com/playwright:v1.53.1-noble` job container and Node.js 24 to match the currently configured Vercel Node major version. GitHub-hosted checkout and Node setup actions use reviewed, immutable Node.js 24-compatible action commits, and checkout does not persist GitHub credentials into the working repository. The explicitly configured npm cache is preserved. The checkout path is `ui-merge-studio` because GitHub's Docker command wrapper failed to start npm in a working directory containing spaces; the real preview-runtime regression creates its own temporary spaced-path alias and verifies cleanup instead.

The version-matched official Playwright image includes Chromium and its Linux dependencies without invoking the runner's Ubuntu package mirrors. GitHub runs #114 and #115 failed during `--with-deps` installation because the mirror's DNS could not be resolved; run #117 confirmed the image pulls but exposed the spaced-working-directory runner failure. Run #119 reached the real Vite lifecycle tests, but process-group cleanup remained blocked by surviving processes after SIGKILL. Run #120 then passed the full unit suite, fixture contracts, Showcase verification, and build using Docker `--init` (Playwright's recommended orphan reaper); the first browser preflight stopped on a shell mismatch before Chromium launch, so it now explicitly uses Bash. The preflight checks the installed Playwright version against the lockfile and launches and closes a real Chromium process before any browser suites begin. **The image change does not establish faster execution or browser-level correctness by itself**; only a complete green CI run can establish that the mandatory suites passed. The overall 40-minute job timeout, browser selectors, source-cleanliness gate, and eight named specs remain unchanged.

The workflow uses same-ref concurrency cancellation (`cancel-in-progress: true`): if GitHub schedules a second run for the same branch/commit, the earlier run may show Cancelled. Evaluate the latest completed run for the exact SHA; do not treat an older cancelled run as a product failure or as proof that the latest run succeeded.

**Deployment ordering:** Vercel Git integration may publish a successful build from `main` before this independent GitHub Actions workflow finishes. A Vercel `READY` state and matching production alias prove deployment alignment, **not** a passed post-merge test suite. The existing workflow does not enforce required GitHub checks or Vercel Deployment Checks. Release verification therefore requires checking the successful *post-merge workflow* at the exact production commit separately; enforcing pre-production deployment gating is an open repository/platform configuration decision, not implemented by this document.

From the committed lockfile the workflow runs:

1. `npm ci --no-audit --no-fund`.
2. `npm run fixture:create` to generate a **disposable** controlled Git repository in the CI checkout (not in the original repository).
3. `npm run typecheck` and `npm test`.
4. `npm run fixture:verify` to assert controlled branch topology and relevant negative/inclusion/exclusion contracts.
5. `npm run showcase:validate` and `npm run build` to check the committed hosted evidence and bundle.
6. A bounded Chromium Playwright product-journey suite from four existing specs: `guided-experience.spec.ts` (hosted/local boundary and keyboard entry), `showcase-evidence.spec.ts` (desktop/mobile selection → combine → evidence, negative refusal and recovery), `integration-plan.spec.ts` (canonical plan identity, configured runtime, history, and non-matrix combinations), and `foundation-support.spec.ts` (pinned Main/A/B foundation semantics, incompatible-foundation refusal, mobile keyboard and undo). These are four explicit Showcase specs; the verified UMS-20 workflow (22 October 2026, run #39839555057) passed **14 Showcase browser tests**. The count is a dated result, not a permanent assertion; CI selects exact filenames rather than a wildcard that could silently include external tests.
7. **Controlled local-engine browser proof** via exact Playwright selectors `local-canonical-plan.spec.ts` and `local-selection-provenance.spec.ts`. Against the disposable, generated **project-owned** Product Catalogue Git fixture, these start real isolated branch previews, select rendered components, verify a canonical plan, generate and verify a Git candidate, exercise its live preview, and assert source/branch/worktree cleanup. The negative path rejects browser-forged source metadata and an unknown receipt before Git mutation. These tests run in CI only, never against production or external repositories.
8. **UMS-09 real browser candidate proof:** execute `two-feature-candidate-browser.spec.ts` in the already installed CI Chromium. It synthesizes two project-owned React/Vite feature branches, selects them through the trusted authority, verifies the candidate with real TypeScript and Vite build tools, starts a temporary Vite server in the verified candidate worktree, and checks both features render and survive browser reload without page errors or unrelated source. Worktree, server, and fixtures are removed after testing; this is **not** an external repository or live production journey.
9. **UMS-25D CSS Module visual-difference evidence:** execute `css-module-real-candidate.spec.ts` in Chromium against a synthesized, disposable `phase0` Git candidate. The test captures the same 1280×720 browser viewport at baseline, after Vite compiles the transferred CSS Module, and after disabling only the compiled stylesheet. It records exact base/feature/candidate commit IDs, candidate tree, bounding boxes and horizontal-shift deltas in `geometry.json`. The workflow uploads only `test-results/ums-css-module-visual-evidence/` as a 14-day `ums-css-visual-evidence-<PR-head-SHA>` artifact (or push SHA on `main`); pull-request workflows test GitHub's checkout merge ref while the name records the PR head, even when subsequent checks fail; if the test fails before capture, the artifact may be absent or incomplete. These files are synthetic, ignored in source Git and intentionally contain no external repository screens or arbitrary logs. **They are inspection evidence, not a visual-acceptance result, screenshot similarity assertion, or authorization to merge.**
10. Repeat `npm run fixture:verify` after browser tests to confirm the fixture is still clean and satisfies all base/branch contracts.
11. `git diff --exit-code` to detect unexpected tracked-source modifications.

A green run proves only that these exact checks passed for the reported commit. It is **not** proof of arbitrary React repository support, external dependency isolation, other Playwright journeys outside the eight explicitly named specs, a live deployment, arbitrary local-repository candidate generation, or production candidate generation.

## Deliberate exclusions

The `external:prepare` and `test:e2e:external` families are **not** part of automatic CI. They may clone/install/execute unrelated repositories and require separate review of network, lifecycle scripts, and isolation. The remaining local-engine/browser suite and external-adapter journeys are also **not** silently treated as covered by the two named controlled local proofs. Fixture-owned npm installation/build and local process execution are intentional and scoped to ephemeral CI worktrees; these checks do not isolate untrusted package lifecycle scripts or prove arbitrary-repository safety.

This workflow does not set GitHub branch protection or make checks mandatory for merging; that is a separate repository-policy decision. PR merge and production changes still require explicit authorization. The **exact job/check name** to select as a required GitHub or Vercel check is `Typecheck, tests, build, and browser journeys` (source: the `verify` job's `name` in [verify.yml](../.github/workflows/verify.yml)); do **not** select `Vercel Preview Comments` as a test gate. A source-code regression guards that name but **does not configure or prove that any remote protection is enabled**. See the [UMS-22 release-protection rollout](release-protection-rollout.md) for the platform-admin activation checklist and the [UMS-21 readiness audit](product-readiness-audit.md) for the claim boundaries.
