# Codex Prompt 007 — Validate UI Merge Studio Against FlowCraft

## Objective

Perform the first real-repository validation of UI Merge Studio using FlowCraft.

Prove or falsify this claim:

“A developer can run two FlowCraft branches as live applications, visually select one meaningful feature from each, trace those selections to real source and dependencies, and create one verified combined branch while excluding unrelated changes—or receive a correct, evidence-backed refusal.”

This is not another fixture milestone.

This prompt must determine whether the architecture generalizes beyond the controlled Support Dashboard.

Preserve the controlled demo and all Prompt 001–006D behavior.

Do not claim universal React support.

Do not optimize for a forced success. Correct refusal is acceptable and preferable to a fake merge.

---

Codex usage is limited.

Work efficiently:

1. Inspect first.
2. Reuse existing architecture.
3. Avoid broad refactors.
4. Run focused tests during development.
5. Run the final command matrix once.
6. Produce a concise report.
7. Stop when decisive evidence is obtained.

Do not repeatedly run long browser suites.

Do not rewrite UI or engine packages unless required by a demonstrated FlowCraft incompatibility.

Do not create mockups.

# Non-Negotiable Product Rule

The visual layer must causally constrain source integration.

Every generated source change must trace to:

1. a confirmed visual selection; or
2. a required dependency of that selection.

For every included declaration or file, the system must be able to explain:

- which selected feature required it;
- the dependency edge;
- the source branch and commit.

For every excluded FlowCraft branch change, the system must explain why neither selection requires it.

If the output is effectively “merge branches broadly and let AI clean it up,” mark the experiment ABANDON.

# Acceptance Outcomes

## PASS — successful integration

Prompt 007 passes strongly if:

1. two real FlowCraft branches run;
2. real FlowCraft UI maps to source;
3. inspector and replay dependencies are traced;
4. unrelated changes are excluded;
5. a deterministic combined branch is created;
6. FlowCraft verification passes;
7. the combined app launches;
8. both features work visually;
9. visual selections causally constrain the code plan;
10. source branches remain unchanged;
11. cleanup succeeds.

## PASS — correct real-repository refusal

Prompt 007 may also pass if:

1. both real branches run;
2. real FlowCraft source mapping works;
3. dependency analysis reaches meaningful real architecture;
4. a precise incompatibility is found;
5. the tool refuses before accepting a branch;
6. the explanation identifies exact shared code/state;
7. no source branch changes;
8. cleanup succeeds;
9. the refusal demonstrates value beyond a generic merge attempt.

Label this outcome:

PASS — bounded real-repository refusal

## MODIFY

Use MODIFY if:

- FlowCraft starts but mapping or dependency analysis fails on addressable patterns;
- candidate generation fails due to a bounded missing capability;
- the system includes unrelated changes;
- the visual plan is not causally tied to selection;
- verification or cleanup is unreliable.

## ABANDON

Recommend ABANDON if:

- the controlled fixture architecture does not generalize at all;
- normal FlowCraft components cannot map to source;
- dependency analysis is fundamentally fixture-specific;
- successful output requires broad branch merging;
- difficult integration is delegated to an LLM;
- the visual selection has no meaningful effect on output;
- a simple AI-agent prompt is clearly better across precision, effort, and trust.
