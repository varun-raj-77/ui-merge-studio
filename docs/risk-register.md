# Risk register

| Risk | Mitigation |
|---|---|
| Hosted replay appears to perform Git operations | Persistent sample label, explicit local-engine explanation, and replay wording near evaluation. |
| Visual highlight misses the real control | Linked feature regions and browser assertions that required control centres fall inside their regions. |
| Evidence drifts from selections | Instrumented browser selections drive analysis; preparation writes a hashed run report and typed replay manifest that build validation checks. |
| Unrecorded combinations look successful | Only the committed safe pair replays success; every other unproven pair is labelled unrecorded. |
| Incompatible selection mutates source | Contract compatibility is evaluated before candidate work and produces a plain-language refusal. |
| Fixture-specific semantics leak into the engine | Product names remain in Showcase metadata and controlled fixture source, never generic analyzers. |
| External proof is overgeneralized | README and limitations explicitly bound it to one conventional Vite repository. |
| Integration-boundary expansion absorbs unrelated co-located behavior | Prompt 014 preserves the failing candidate/tree. Prompt 015F limits `replace-jsx-region` to structural AST direct-child insertion with unique parent/anchor and declaration-shell preconditions. Expression overlap and every failed projection refuse before worktree creation; there is no region-to-declaration fallback. Prompt 015G moves the controlled happy path onto that same boundary: both controlled integrations use `insert-child`, promotion/inventory changes remain excluded, and the historical declaration-wide shapes still refuse. The unrelated external density/footer exclusions remain the non-fixture control. |
| Temporary processes or worktrees leak | Controllers use explicit lifecycle cleanup and verification tests audit cleanup. |
| A moved foundation or source ref changes a published plan's meaning | Plans pin exact commits; generation resolves current refs and refuses stale branch heads before mutation. |
| Foundation UI is mistaken for partial feature selection | Plain-language descriptions and a separate dock group state that all foundation changes are included. Same-branch additions normalize away. |
| Merge-base assumptions lose foundation work | Git resolves and pins the common ancestor; integration tests compare every foundation-changed path against the candidate. |
| Overlap is refused too broadly or accepted unsafely | Ordinary file overlap is analyzed structurally; stable shared-contract replacement produces a product-language refusal before candidate presentation. |
| Hosted preview appears to check out a selected foundation | The result is labelled Configured preview; documentation and UI reserve actual Git/worktree claims for the local engine. |
| Normal browser flow supplies source evidence or replays stale/session-invalid evidence | The preview transform registers random receipt-to-source mappings through a session-private process channel. Normal browser messages and public analysis requests contain only opaque receipts; raw source identities are refused. The normal generation request contains only Integration Plan V2 plus its identity, which is recomputed and matched to current session-owned analysis, pinned commits, repository, foundation, and common ancestor. |
| Receipt provenance is mistaken for proof of a physical click | Phase 0 explicitly trusts the local developer and local browser/processes. A developer can inspect transformed Vite modules, recover a registered current-session receipt, and call the localhost API directly. Receipts protect the normal product path from browser-authored source authority; they do not attest to human intent or defend against deliberate local bypass. |
| A second semantic payload diverges from the canonical plan | The local App no longer sends raw artifacts. The server derives the generator request exclusively from the validated plan and its private analysis registry, and carries the same identity through preflight, report, verification, and final preview state. |
| READY hosted deployment is described as proof of a generally deployable Git merge engine | Separate the published controlled Showcase from localhost candidate generation; preserve explicit hosted vs local copy, latest limitations, and the [UMS-21 capability matrix](product-readiness-audit.md). |
| A production Git push deploys before independent post-merge tests finish | An automatic Vercel deployment may become READY while GitHub CI still runs. Verify post-merge CI independently at the exact production SHA; consider Deployment Checks/branch policy only after separate owner-authorized configuration review. |
| The last generation-status snapshot is mistaken for durable job history or multi-user isolation | UMS-17/20 give exact-plan/generation ownership but no persistence, per-user authentication, historical queue, or remote cancellation. Clearly label the single latest-attempt scope and require separate proof before multi-user claims. |
| Local dependency installation is mistaken for sandboxed execution | Detached worktrees separate the original checkout but do not contain network, untrusted package lifecycle scripts, or local OS side effects. Limit evaluation to trusted local repositories; no arbitrary-code safety claim. |
| External React/Vite proof is overgeneralized from bounded historical evidence | Record the single unrelated repository's missing application-owned tests and outstanding exact rerun, then require an additional unrelated repository with meaningful application tests before expanding validated compatibility claims. |
